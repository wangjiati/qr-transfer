# QR 文件传输

单文件工具：通过二维码动画在隔离虚拟机与宿主机之间传输小文件。零依赖、完全离线。

## 快速开始

交付物只有一个文件：`qr-transfer.html`，拷到两边机器上双击打开即可。

推荐按以下顺序操作（可一圈收完，避免等循环补齐）：

1. **宿主机**打开 `qr-transfer.html#receive` → 点「开始抓屏」→ 选择**虚拟机窗口**（不建议整屏）
2. 让发送窗口保持可见（不要最小化或被完全遮住）
3. **虚拟机内**打开 `qr-transfer.html#send` → 拖入文件 → 按需调整帧率/分片 → 点「开始」
4. 接收端收齐后自动校验 SHA-256 并下载；完成后可点「重新下载」

接收端支持从循环任意位置加入（先预收集数据帧，头帧到达后再校验），但中途加入时，开头未采到的分片要等下一圈补齐。所以先开接收端、再开发送端最快。

## 参数与吞吐

| 参数 | 默认 | 可选 |
|---|---|---|
| 帧率 | 5 fps | 2–5 fps |
| 分片 | 600 B | 300 / 600 / 1000 B |
| QR 尺寸 | 自适应 | 400 / 600 / 800 px |

- 理论吞吐 ≈ 分片大小 × 帧率：600B × 5fps ≈ 3KB/s，1000B × 5fps ≈ 5KB/s。
- 实际耗时按 **gzip 压缩后大小** 计算。例：326KB 文本日志 gzip 后约 73KB，按 1000B/片为 73 片/圈，5fps 下一圈约 15 秒。
- 每圈时长 = 分片数 ÷ 帧率；中途加入最坏多等一圈。
- 高分辨率抓屏（2K/4K）或二维码在画面中偏小时，建议把「尺寸」设为 800px 或「自适应」，保证接收端下采样后仍可解码。

## 可靠性说明

- 单向传输、明文：任何能看到屏幕的人都能截获，勿传敏感数据。
- 接收端必须以 `file://`、`localhost` 或 `https` 打开；内网 `http://裸IP` 会被浏览器禁止抓屏。
- 抓屏期间被捕获的发送窗口必须保持可见：Chrome 在窗口被完全遮挡/最小化时会暂停出帧。发送页左下角的小黑点动画是**保活标记**，用于逼使抓屏持续出帧，属正常现象。
- 帧率上限已设为 5fps。实机验证：5fps、1000B/片时，活跃抓屏期间 73 片无漏采，收齐后 SHA-256 校验通过；10fps 会与抓屏出帧节拍混叠，不建议使用。
- 接收端会显示实时统计：`抓屏 rvfc/轮询`、`画面变化`、`解码次数/成功`、`平均解码 ms`、已收分片。若 `rVFC` 长时间为 0，说明被捕获窗口被遮挡或抓屏已暂停。
- 适合 KB–几 MB 级、可压缩的小文件；文件越大，圈数越多、耗时线性增长。

## 诊断日志

接收端 F12 Console 会输出（对象均为单行 JSON，便于整段复制）：

- 环境：屏幕/窗口尺寸、DPR、CPU 线程、抓屏 `getSettings()` / `getCapabilities()`、解码尺寸上限
- 视频就绪：实际捕获尺寸 → 缩放后解码尺寸
- 每秒统计：`抓屏rvfc每秒`、`轮询每秒`、`画面变化每秒`、`解码次数/成功每秒`、`平均解码ms`、`已收`、`坏帧`
- 每帧：`数据帧 {seq, 新分片, 已收}`
- 每圈头帧重复时：`{已收, 缺失总数, 缺失序号}`——用于判断是否系统性漏帧
- 解码失败、rVFC 无新帧告警（5 秒限频，传输完成后静默）、校验失败

发送端 Console 输出启动参数（fps、帧数、分片、QR 版本、画布/屏幕/窗口/DPR）与每圈实际耗时、平均渲染耗时。

排查建议：

- `画面变化 ≈ 发送 fps`、`解码成功 ≈ 画面变化` → 正常
- `画面变化 < 发送 fps` 或每圈缺失序号固定 → 抓屏漏采，确认发送窗口可见
- `抓屏rvfc每秒 = 0` → 抓屏暂停/窗口被遮挡
- `平均解码ms` 明显接近 200ms → 降分辨率或改用更小分片/更低帧率

收集到的日志可放在 `test/log/`（已加入 `.gitignore`，不会提交）。

## 开发

- 页面内自测：打开 `qr-transfer.html#test`；当前 29 个用例。
- 命令行自测：`bash test/run-tests.sh`（需本机 Chrome/Edge）。
- 应用代码在 `qr-transfer.html` 尾部 `<script>` 内，按锚点分区：`__PROTOCOL__`（帧编解码）、`__PIPELINE__`（压缩/校验/重组）、`__QRIMAGE__`（QR 渲染/解码）、`__SENDER__`、`__RECEIVER__`、`__TESTS__`（自测用例）。
- `vendor/` 是两个内联库（qrcode-generator、jsQR）的原始存档，仅作来源留存，不被页面引用。
